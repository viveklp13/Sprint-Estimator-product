# Sprint Estimator Column ADO Export Field ADO Work Item Type Notes

⚠ Fields Requiring Manual Input After Import

  • Org Productivity — Organization-specific value (e.g. 1.5–2.5); not tracked in ADO
  • Man Days Hours — Your team's hours/day (e.g. 7 or 8); not tracked in ADO
  • SIT Defects — Count of bugs found in System Integration Testing; pull from ADO Bug query
  • UAT Defects — Count of bugs found in UAT; pull from ADO Bug query
  • Actual Req / Design / Testing / PM MD — Phase effort breakdowns not captured per-story in ADO

✅ Fields Auto-Derived From ADO Data

  • Feature Start Date — Min of child User Story "Start Date"
  • Feature End Date — Max of child User Story "Target Date"
  • Is Completed — State = "Done" or "Closed" or "Resolved" → TRUE
  • Story Man Days — Original Estimate ÷ Man Days Hours (calculated by SE)
  • Story Points — Story Man Days × Org Productivity (calculated by SE)
  • DRE — SIT ÷ (SIT + UAT) × 100 (calculated by SE)

📖 How to Export from Azure DevOps

Step 1 — Create a Flat Query in ADO

Go to Boards → Queries → New Query. Set query type to "Flat list of work items".

Work Item Type = Epic OR Feature OR User Story
AND Team Project = [Your Project]
AND Iteration Path UNDER [Your Sprint/Release]

Step 2 — Add Required Columns to the Query

In the query results, click Column Options and add these fields:

ID
Work Item Type
Title
State
Area Path
Iteration Path
Story Points
Original Estimate
Completed Work
Start Date
Target Date
Activated Date
Resolved Date
Tags
Parent

Step 3 — Export to CSV

Click the ⋯ More options menu in the query results toolbar → Export to CSV. The file downloads as WorkItems.csv.

Step 4 — Handle Hierarchy (Parent Mapping)

ADO exports a flat list. To get the parent Feature name for each User Story:

  • In the exported CSV, User Story rows have a Parent ID that points to a Feature row
  • The converter tool on this page handles this automatically via the Parent column
  • Alternatively, run a Tree of Work Items query type and export — this shows parent-child directly

Step 5 — Get Defect Counts (SIT / UAT)

Run a separate Bug query filtered by tag or iteration to count SIT vs UAT defects:

Work Item Type = Bug
AND Tags CONTAINS "SIT" → SIT Defects count
AND Tags CONTAINS "UAT" → UAT Defects count

Add these counts manually to the Sprint Estimator import or Productivity Tracker.

Step 6 — Upload to Sprint Estimator

Use the 🔄 Live Converter tab to convert your ADO CSV to Sprint Estimator format, then upload via 📊 Import Excel → Upload & Import in Sprint Estimator V4.
